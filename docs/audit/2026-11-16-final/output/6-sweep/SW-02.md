# SW-02 · Shared trace host dependencies (X1-014)

The chart frame and timeline now declare their existing trace host classes at
the elements that use them. The production search
`rg -n 'import .*@/pages/' web/src/components --glob '!*.test.*'`
found two page imports before and zero after. Both carried only the
`TRACE_HOST` string from `pages/library/parts/TraceControl.tsx`.
The change removes two net source lines.

Base `f691836e` (application source `5e1d98b3`), source commit
`e27ca3f7eb32a4484206e7c8690bc2be566fabe0` on
`audit/sweep-trace-boundary`. Source files are
`web/src/components/chart/ChartFrame.tsx` and
`web/src/components/timeline/Timeline.tsx`.

The exact literals are the smallest way to preserve the classes while
removing the imports. The alternative of moving the constant into another
module either redirects every page caller or introduces a re-export.
Shared chart tables and metric cards already use these two tokens directly.
The existing page export still serves the pages that import it.

The confidence check compared the chart figure's exact class string and
used the real `cx` helper to compare the timeline item classes for absent,
present and null actions. The chart remains
`group/trace relative flex flex-col gap-4`. The timeline still adds the
named group and moves the merged `relative` token to the same position
when a slot is present, including a null slot. The page-owned trace
control and the protected Signal files match the base byte for byte.
