# SW-03 · Repeated chart frame props

X1-025. Discovery base `f691836ecff6ab8c69f85302b562e25617a3f31c` (application
`5e1d98b37305a9da59fb6944740ff17b721051af`). Source
`e3848445d08bbd3e749c4e068fb3941f17bfdbbb` on `audit/sweep-chart-duplicates`.

ColumnsChart, ScatterPlot and StackChart passed the same five frame props
individually to ChartWithTable. Each now unpacks its own data inputs and passes
the remaining frame props directly to the existing wrapper. This removes 27
source lines and retains the same chart titles, actions, initial Chart view,
table switch and `detailTable ?? table` selection. Each chart still validates
its plotted table before rendering. The table and chart labels and source
strings flow through the existing components.

The identical command `timeout 300 npm --prefix web run duplication` exited
0 before and after. Both runs used the existing jscpd 5.4.1, Node 24.22.1, npm
11.9.0 and configuration. The reports match on 285 clone identities when
compared by file pair, format, line count and token count. The two removed
pairs are ColumnsChart with ScatterPlot and ColumnsChart with StackChart,
each 10 lines and 51 tokens. The comparison found zero added pairs.

The confidence review followed both kinds of caller. Static model charts
typically omit `detailTable`, while connected visuals use it to retain the
full original source table. The two branches still pass the same selected
table to the same wrapper. Optional `as`, `note`, `subtitle` and `actions`
are received as undefined when omitted in either form. ChartWithTable owns
the same ChartFrame instance and toggle state. The simpler direct forwarding
avoids another wrapper and leaves each chart's data-specific code in place.
