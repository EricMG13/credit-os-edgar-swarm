### Design choices the lead should know

1. **The connected app is a multi-page app** (`connected-main.tsx` reads `window.location.pathname` once; the rail links and
   `navigate()` are real document loads). State kept in memory cannot survive a Library link, Reload or Back to another page.
   Restoring from storage would need a stored draft id and the files already uploaded, which is exactly what T10 (abandoned
   drafts) is about to clean up. So the repair does what the finding's suggested change names first: a history entry per step,
   and a browser confirmation before the page is left with work in it. It creates no draft and keeps none; what Submit sends and
   what the approval digest binds are untouched (`makeAnswers`, `prepareReview` and `submitReviewed` are unchanged except one
   flag set just before `navigate`).
2. **The case date still opens at today's date.** (Round 1. Superseded in Round 2: a new form now opens with the date empty.) The finding's title names it, but its probe and verdict test the example
   issuer only, CT-003 says the date is the user's (it is: the field is editable and required), the page already tells the
   analyst "Set to today for the new run" and J1-015 treats today's default as the page's normal behaviour. Emptying it would be
   one line in `startingContext` (`as_of: today()`); it is left for the lead or the owner to say.
3. **Carry-over keeps only what the earlier run recorded.** The run records `attachments.legal_documents` (a choice) and
   booleans for the workbook, bridge and prior case; it does not record which file filled any role (checked in
   `run_start/prior.py` and the probe's `earlierAnswers`). So the Legal documents choice is applied, and the page says which
   file choices were not recorded and must be made again on More context. No file is chosen by reading the documents.
   With the choice applied, the analyst who has not chosen the agreement is told so on the control ("Choose the uploaded file
   that is the agreement.") instead of reaching a review that says "Will refuse: Legal & covenants".
4. Back from the review sheet returns to More context (the review is cleared through the existing `editReviewedInputs`, which
   keeps the decisions for the next review of the same issuer and pathway). Forward onto a review the page no longer holds, or
   onto a step whose documents were changed after it, is passed over with `history.back()`; nothing is rebuilt or requested.
5. After Submit, browser Back from the run page still opens a blank form (J2-001's last clause): the submitted form is not
   restored, because a second Submit of a consumed draft would be wrong. Not changed.
