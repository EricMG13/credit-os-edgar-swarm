## Finding

C1-013 (Medium): run reasons were drawn exactly as the scheduler wrote them. The launcher's
`launcher exited 2; see logs/<run>.log` reached the red alert on `/run/<id>` and the Reason column
of Ended without a report; the library's refusals (`not listed: ... CP-1's handoff
(deliveries/<sha>/view.json is missing)`) carried a module code and a delivery path. RunActivity
and RunProgress drew `reason`, `held` and `held_reason` without `serviceText`.

## What changed

Two layers, one choke point each.

1. `react_frontend/run_activity.py` (the one place every run reason and held note leaves the
   service for the browser). New `_in_readers_words`, applied inside `_shown`, which already
   stripped the root path. It maps the scheduler's own failure reasons to a sentence that says what
   happened and what to do. Nothing is invented: each sentence restates what the scheduler's text
   says and gives a next step. The stored reason, with its exit code, log path, file names and
   module codes, is untouched in the run record (`_engine/state/<id>.json`) and, for the paths the
   scheduler logs (a failed start, a failed filing, an unsaved record), in the operator log; it is
   no longer sent to the browser. `listing` also passes the
   `held` note through `_shown` now (`reply` already did for `held_reason`), so a root path in the
   held note is no longer sent.

   | Stored by the scheduler | Sentence for the reader (what happened; what to do) |
   | :--- | :--- |
   | `launcher exited N; see logs/<run>.log` (N may be negative: a launcher killed by a signal; round 2) | The run ended before it finished, and the service recorded no reason. Start from this run to try again; if it ends the same way, ask whoever runs the service to check the run's log. |
   | `stopped: provider` | Stopped because of a problem with a model provider call, not the spending cap; try again. |
   | `stopped: checker` | Stopped because a module's answer did not pass the checks; try again. |
   | `stopped: interrupted` | The run was interrupted before it finished; try again. |
   | `stopped: ruling` | The approval that lets the service make paid model calls was not in place for this setup; starting again will stop the same way until whoever runs the service puts it in place. (Round 2 wording.) |
   | `stopped: <any other kind>` | Stopped for a reason the service did not classify; try again, then ask whoever runs the service to check the log. |
   | `not listed: <why>` | The run finished, but the library would not list it, so it has no report; try again, then ask whoever runs the service to check the run's record. |
   | `expected one deliveries/*/delivery.json, found N` | The service did not find exactly one delivery for it, so it has no report; same next step. |
   | `could not be filed: <error>` | The service could not file its report; ask whoever runs the service to check the service's log before starting again. (Round 2 wording.) |
   | `could not be started: <error>` | The run could not be started, so it did not run; ask whoever runs the service to check the service's log, then start again. (Round 2 wording.) |
   | `stopped by the scheduler: its record could not be saved (<error>)` | The service stopped this run because it could not save the run's record; ask whoever runs the service to check the service's log, then start again. (Round 2 wording.) |
   | `no context.json in _engine/drops/<run>; submit it again from the run page` | The run's submission record was missing, so it was not started; to try again, choose Start from this run on the run's page. (Round 2 wording.) |
   | `the library could not be rebuilt (<error>); ended runs wait for it` (a held note, alone or first of several joined with `; `) | The library could not be rebuilt, so runs that have ended wait to be filed; the service tries again on each check; if this stays, ask whoever runs the service to check the service's log. (Round 2.) |

   Left as stored because they already read plainly and carry no code or path: `stopped at the
   cap`, `the run's process ended without a result`, the "service stopped while starting"
   text, the old folder-watcher text, "the submitted documents changed before the run could
   start", the daily-limit and unreadable-record held notes. Any reason the table does not know is
   sent as before (root removed, other absolute paths cut to their last segment).

2. `web/src/pages/connected/RunActivity.tsx` and `RunProgress.tsx`: every service-written string
   they draw (`run.reason` in the Ended table, the running card and the waiting row; `held` and
   `held_reason`; the failed-run alert) goes through `serviceText` (`api.ts`), which replaces a
   module code by the module's name. That covers a reason or held note the table does not know and
   the case where the browser is handed text that did not come through the service.

Where the detail lives: the AGENTS.md voice standard draws source references, file names, hashes,
ids and run codes only on the Evidence page and trace drawer of a published report. A run that
ended without a report has neither, so the exit code, log path, delivery path and refusal text have
no place on these two pages and are not sent to them. They remain in the run record on disk (and in the scheduler's log
where it writes one).

### Judgement calls

- A held note that carries the rebuild note and then another note reads "...service's log. daily
  limit of N runs reached; waiting until tomorrow": the second note is kept as stored, so it
  starts in lower case after the full stop. It is the existing form of that note, and the two
  failing together is rare; the alternative, a trailing `;` on the first, would leave a sentence
  with no full stop in the usual single-note case.
- The test imports the private `_REBUILD_FAILED` from the scheduler, as the task asked, so a change
  to the scheduler's text makes the case fail loudly instead of passing on a stale copy.
