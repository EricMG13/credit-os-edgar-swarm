## Implementation (round 1, Opus 5.5, medium)

- C3-007: `getSnapshot` now throws a `RequestError` carrying the HTTP status. `ReportReader` loads
  through `loadReport`, which turns a failure into a designed state instead of the raw message: a
  network failure ("The report service could not be reached", with Try again, which remounts the
  reader and reads afresh); any other service error ("The report could not be loaded", Try again
  and Run activity); a 404 reads the run's Run activity record and says "This run is still going"
  (queued or running; J2-016), "This run ended without a report" (failed, capped, rejected,
  interrupted; J5-007), "No report is listed for this run" (finished but not listed), or "No report
  at this address" (no run record), each with Run activity and/or Back to the library. All use the
  approved `Alert` (tone by severity, one action row). No raw error string is drawn.
- C3-008: `runLabels` (publishedReport.ts) applies ruling H7 as the legacy library does
  (`reader.js` `earlierFormatRun`): any handoff of the run, every saved output of every module,
  whose `## Findings` has a first H3 other than `### Bottom line` makes the run "Earlier format"
  (a handoff not held, or the build's "Unstructured handoff", says nothing); a non-empty
  `methodChanges` (the store's `method_changes`, now typed on `PublishedRun`) makes it "Earlier
  methods". The labels are badges in the run frame's header, so they show on Overview, Changes and
  every other tab.
- C3-024: `overviewCharts` (reportView.ts) selects, in run order, the drawings of the catalogue
  rows placed on Overview that are charts, by owning module and the fixed heading the module
  publishes them under (`owners/cpos_launch_tables.py`): CP-1A-V01 `Events: Issuer history`,
  CP-DR-V03 `Events: Research catalysts`, CP-2-V02 `Map: credit-risk transmission`; a gap, a parse
  error or a blocked module gives none. Overview draws them under "Key charts", after Limitations
  and before Dates to watch (H5 order), with the existing `LegacyVisuals` (as the Forecast tab's
  Run charts do), a link to the owning module, and a "Chart index" link to `#forecast`.
- C1-007: each Report history row now shows "N modules run: <plain names in run order>", the
  Finished status (every run the snapshot lists is published) and the run's labels. The page's
  snapshot carries only date and pathway for the issuer's other runs (`react_frontend/sources.py`
  `scoped`), so each other row reads that run's own scoped snapshot (`/connected/snapshot?run=`).
- C3-026: `moduleBottomLines` and `runLimitations` walk the run's modules without CP-8
  (`overviewModules`); CP-8's findings stay on Changes.

## Decisions

- Key charts are the catalogue's Overview rows that are drawings. The "Table/content only" rows
  (CP-2-V03 Monitoring triggers, CP-2D-V02, CP-5-V01) and CP-0-V02 (a readiness table on CP-0's
  page, not a published chart) are not charts and are not repeated: repeating tables is not what
  H5.4 asks and would add Overview content no ruling places there. CP-MODEL-V02 is the "Chart
  index" link (Forecast holds every run chart); DELIVERY-V02 is the existing Dates to watch. The
  catalogue is not loaded by the app (harmony H-14), so the three rows are fixed in code beside
  their catalogue ids.
- When a run has none of the three, Overview says "No key chart has data in this run." and keeps
  the Chart index link.
- Labels sit in the run frame header (CM-031 run label), not in the body, so one placement serves
  Overview (CM-048) and Changes (CM-060). "Earlier methods" follows the run's own `methodChanges`,
  as the legacy library does; the CM-060 clause "whose earlier run used earlier methods" is not
  applied separately (the scoped snapshot does not carry the earlier run's list, and the legacy
  library does not apply it either).
- The 404 case asks Run activity for the run's state so the sentence says what is true (running,
  ended, finished but unlisted, or no run) rather than one hedged sentence.
- Report history sort is unchanged (as-of date only); CM-032's start-time tie-break was not part
  of the finding.

Not verified: the "No report is listed for this run" state (a finished run the library does not
list) and the "The report could not be loaded" state for a server 500 were exercised only in vitest
and code read, not against `proof.serve`; a history row whose other-run snapshot fails to load
("could not be read") was not exercised; Earlier format / Earlier methods on a real stored run
(proof.serve cannot make one; p08 rewrites the snapshot in the browser); CP-1A and CP-DR key
charts on Overview (the synthetic run draws CP-2's map; CP-1A's issuer-history lane did not reach
Overview in the probe's titles because the probe only lists headings matching its own pattern, so
it was not separately confirmed); C3-025 (navigator search) keeps p15 at exit 1 and is another
task's finding; no screenshot was taken (tests cover each finding).
