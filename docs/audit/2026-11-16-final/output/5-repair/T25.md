# T25 (group 3): Static app says it is a design reference; the kit leaves the rail

Base: `99ceeed` (`audit/repair-3`). Rulings: OQ-01 and OQ-05, accepted under R10.

## Findings

- S6-003 (with J6-010), Medium: the static run pages did not say they are a saved example, and the Start
  step's dialog and Run started claimed a run was started.
- S1-004 (with X1-018), Medium: the component kit was a rail item of the static app.

## What changed

- `web/src/shell/Shell.tsx`: Kit is no longer a rail item (the `Area` type keeps `kit`, so the kit page is
  still drawn inside the shell, with no rail item marked current).
- `web/src/App.tsx`: one note, "Design reference with sample data" (the kit's `Callout`, role `note`), drawn
  once ahead of the page, on every populated library page, every populated run page (start steps and run
  activity, padded or bleed) and on `#/kit`. It is drawn only where a slice is read (`slice.kind === "ok"`),
  so the shipped build with no data file, a newer data file and a group with no slice show none. `#/kit`
  stays reachable by address.
- `web/src/pages/run/start/Start.tsx`: the Submit dialog of the static Start step names the saved example
  ("This page shows a saved example: confirming starts no run and spends nothing.") through a new optional
  `note` prop on `SubmitConfirmation`. The connected app's `StartRun.tsx` passes none, so its dialog is
  unchanged (test below).
- `web/src/pages/run/start/Started.tsx`: Run started says "This page shows a saved example, so no run was
  started and nothing was spent." inside the status panel, and the closing line now reads "In a live run you
  can close this page: the run carries on, and its library appears under <issuer> when it finishes." (it
  said "You can close this page. The run carries on ...", a claim that was false on a saved example).

## Tests

- `web/src/shell/Shell.kitRail.test.tsx` (2 tests): the rail names Library, Model, Run, Signal and no Kit; a
  page given `current="kit"` still draws and marks no rail item.

- `web/src/pages/run/start/Start.savedExample.test.tsx` (4 tests): the static Submit dialog names the saved
  example after the paid text; the connected-style `SubmitConfirmation` with no `note` draws none; Run

# Follow-up under ruling L7: the model pages carry the note (S6-003)

Base: `27b00e4` (`audit/repair-3`, after T40's merge). Ruling: L7 (lead, 2026-11-17, in
`output/sessions/repair-3/ANSWER.md`): draw the same "Design reference with sample data" note inside the model
frame through `ModelShell.tsx` and on `RunsIndexPage.tsx`, with the same words as on the other pages; keep the
existing tests; if the "Sample data" badge then says the same thing twice, keep one and name the choice.

Rounds: 1 (follow-up under L7), implementer Sonnet

## Findings

- S6-003 (OQ-01, R10), the part held back from the first round: the model pages (`/model/runs` and the six
  run page forms) said nothing of being a design reference; only a "Sample data" chip in the run header, drawn
  where the fixture sets `header.sample`.

## What changed

- `web/src/shell/DesignReferenceNote.tsx` (new, 16 lines): T25's note, the `Callout` titled "Design reference
  with sample data" with its text unchanged, moved out of `App.tsx` and exported. A new file was needed:
  `App.tsx` imports `pages/route-table`, which imports `pages/model/routes`, so a model page that imported the
  note from `App.tsx` would make a cycle (`App` -> `route-table` -> `model/routes` -> `ModelShell` -> `App`).
  The repo already keeps shared pieces out of `App` for this reason (`SourceContext` is in `pages/source`).
  Nothing was copied: `App.tsx` and the model frames draw the one component.
- `web/src/App.tsx`: its local `DesignReference` wrapper (the `bleed` / padded spacing) now draws
  `<DesignReferenceNote />` instead of the inline `Callout`; one import line swapped and one comment reworded.
  The DOM on every other page is identical (T25's 39 `App.designReference.test.tsx` tests pass unedited).
- `web/src/pages/model/parts/ModelShell.tsx`: the note is the first child of the page's own `p-8` frame, ahead
  of the breadcrumb, so it appears once on each of the six run page forms (front, analysis, statements,
  portfolio fit, limitations, forecast); the `Sample data` badge is no longer drawn (choice below).
- `web/src/pages/model/RunsIndexPage.tsx`: the note is the first child of the page's own `p-8` frame when the
  model slice is read (`slice.kind === "ok"`, T25's rule); a data file with no model shows the "No model has
  been delivered yet" state and no note.

The shipped build (empty data file) never reaches either page (App draws the "Library data is missing" notice),
and a data file with no model slice draws none, so the model pages show no note there, as the other pages do.

## The badge or the note

Choice: keep the note, drop the badge. Reasons: (1) the note is the owner's ruling (OQ-01) and carries its
words, so every static page now says the same thing in the same way; the badge said only "Sample data". (2) The
badge was drawn only where the fixture set `header.sample`, so keeping it and dropping the note on those runs
would leave the one fixture run (sample true) with the chip alone, which is not what L7 asks; keeping both
says it twice. (3) The note is drawn whatever `header.sample` holds, as T25's note is drawn on library and run
pages that have no such flag: the static app is the design reference. Cost: one existing test list edited
(below). `header.sample` is still read by the slice and no longer drawn; the slice is outside this follow-up.
