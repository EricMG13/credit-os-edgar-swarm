# T25 (group 3): Static app says it is a design reference; the kit leaves the rail

Base: `99ceeed` (`audit/repair-3`). Rulings: OQ-01 and OQ-05, accepted under R10.

## Findings

- S6-003 (with J6-010), Medium: the static run pages did not say they are a saved example, and the Start
  step's dialog and Run started claimed a run was started.
- S1-004 (with X1-018), Medium: the component kit was a rail item of the static app.

## What changed

- `web/src/shell/Shell.tsx`: Kit is no longer a rail item (the `Area` type keeps `kit`, so the kit page is
  still drawn inside the shell, with no rail item marked current).
- `web/src/App.tsx`: one note, "Design reference with sample data" (the kit's `Callout`, role `note`), drawn
  once ahead of the page, on every populated library page, every populated run page (start steps and run
  activity, padded or bleed) and on `#/kit`. It is drawn only where a slice is read (`slice.kind === "ok"`),
  so the shipped build with no data file, a newer data file and a group with no slice show none. `#/kit`
  stays reachable by address.
- `web/src/pages/run/start/Start.tsx`: the Submit dialog of the static Start step names the saved example
  ("This page shows a saved example: confirming starts no run and spends nothing.") through a new optional
  `note` prop on `SubmitConfirmation`. The connected app's `StartRun.tsx` passes none, so its dialog is
  unchanged (test below).
- `web/src/pages/run/start/Started.tsx`: Run started says "This page shows a saved example, so no run was
  started and nothing was spent." inside the status panel, and the closing line now reads "In a live run you
  can close this page: the run carries on, and its library appears under <issuer> when it finishes." (it
  said "You can close this page. The run carries on ...", a claim that was false on a saved example).

## Tests

- `web/src/shell/Shell.kitRail.test.tsx` (2 tests): the rail names Library, Model, Run, Signal and no Kit; a
