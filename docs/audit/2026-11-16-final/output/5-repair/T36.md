# T36 (group 3): Limitations header at narrow widths

Findings: S3-003 (Medium, with merged S2-004). At 480 px and below the Limitations header (heading and
count, the gaps link, the collapse button) was one non-wrapping flex row, so it ran past its card, the
page scrolled sideways, and Tab from the gaps link to Collapse limitations moved `#main` 104 px left.

## Files changed

- `web/src/pages/library/parts/Limitations.tsx` (the only source file; the task's file)
  - header row: `flex items-center justify-between gap-3` to `flex flex-wrap items-center justify-between gap-x-3 gap-y-2`
    (the link and button group drops under the heading when it does not fit);
  - link and button group: `flex items-center gap-4` to `flex min-w-0 items-center gap-4` (it may shrink to the card width);
  - gaps link: `className="whitespace-normal"` (the kit link is `whitespace-nowrap`; at 320 px the 259 px link
    in a 208 px card ran 28 px past the card edge, so its text now wraps to two lines, arrow and button kept beside it);
  - collapse button: `shrink-0` (it shrank to 21 to 29 px wide once the link wrapped; stays 32 px).
  DOM order is unchanged, so reading and Tab order stay heading, gaps link, Collapse. At 480 px and wider the
  row is still one line (link 20 px high at 480, 768 and 1440; no change on desktop).
- `web/src/pages/library/parts/Limitations.narrow.test.tsx` (new, beside the component).

## The test

`Limitations.narrow.test.tsx` renders `Limitations` and asserts the layout classes that carry the reflow
(jsdom has no layout engine, as in `ResponsiveReading.test.tsx`; the probes carry the pixel proof):
header row `flex-wrap`; group `min-w-0`; gaps link `whitespace-normal`; collapse button `size-8 shrink-0`;
and a guard that heading, gaps link and collapse button stay in that document order.
