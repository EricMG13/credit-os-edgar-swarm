## S2-005: cause and repair

The register's cause (`max-w-full` on a Badge whose inner span is `size-max`) is not the whole of it.
`Badge` is one span, `size-max flex ...`, and its `max-w-full` and `whitespace-normal` do apply. The
cause is the column that holds a point's sentence and its badge (`Overview.tsx`, the
`div.flex.min-w-0.flex-1.flex-col.items-start`). Its parent stacks at narrow widths with
`items-start`, so the column is not stretched: its width is `fit-content`, and the badge's
`size-max` makes the column's min-content as wide as the whole qualifier on one line (446 px at 390 px,
measured in the browser against a 276 px content box). The badge's `max-w-full` is a share of that
446 px column, so it never wraps. At 1440 px the row layout (`@md:flex-row`) gives the column
`flex-1 min-w-0` on the main axis, which is why it wrapped there.

Repair: one class, `max-w-full`, on that column (`web/src/pages/library/Overview.tsx`, `PointTile`).
It gives the column the tile's width, so the badge's own `max-w-full` has a definite width to wrap
within. In the row layout the column's width is already set by `flex-1`; `max-w-full` changes nothing there.

## S2-006: why it is blocked

The finding's repair is an optional `trace` on `DatedItem` (`slice.ts`), read in `read.ts`, and one
`TraceControl` per entry drawn by `Overview.tsx`. `Overview.tsx` draws the entries through the shared
`Timeline` component, and `Timeline` has no place to put a control: its item is
`{ date, title, text?: string, state }`, and it draws the title in an `h3` and the text in a `p`, both as
plain strings. Nothing in the three listed files can put a control inside an entry (a control beside
the list cannot be tied to its entry; rewriting the list in `Overview.tsx` would copy the approved
Timeline). Two more files are needed, and the brief puts both out of reach:

1. `web/src/components/timeline/Timeline.tsx` (not on T33's list): an optional per-item slot (for example
   `action?: ReactNode`, and a way to mark the entry as a trace host so the control's hover reveal
   works). It is used by `Kit.tsx` and `cards.test.tsx` and, from the library, by `Overview.tsx` only;
   Signal does not use it. No other group-3 task lists it (X1-001 and X1-010 are Low and Info batch
   findings that touch it later).
2. `web/fixtures/library.json` (barred by the brief): the four `dates` arrays (lines 518, 4076, 4969
   and 5955 of the fixture) carry no `trace` key. `read.ts` treats an absent field as malformed
   ("an absent field is not missing, it is malformed"), so either the key becomes optional for dates
   only, in which case the shipped fixtures still draw no control and the probe output does not change;
   or the fixtures carry `trace` (a key of the run's traces, or an explicit null) on each date,
   which is a content choice (which module trace each date belongs to, CM-043) that is not the
   implementer's to make.

Also for the follow-up: `Overview.test.tsx` "draws the four dates with their state words, shapes that
differ by state, and no trace" (line 349) asserts `queryByRole("button")` is null inside each date.
That asserts the defect and must change with the repair; `read.test.ts` (dates, lines 544 to 692) needs a case for
the new key. T35 changes `TraceControl` at the same time (a marker where a trace is null), so
a date with a null trace will draw that marker once T35 lands; decide whether dates take
an explicit null or an absent key before the follow-up. The finding's alternative (record in the ruling that
dates are exempt) is the owner's, not the implementer's.
