# T27 (group 3): Static route change: title, focus and scroll

Base: `65ca715` (`audit/repair-3`, with T25's and T26's merged changes). Ruling: none beyond R10 and the
task note (no OQ cited).

Round 2 (owner rulings R14 and R16, 2026-11-17) removed the route-change focus moves and the screen-reader
announcement that "What changed", "Tests" and "Probes" below describe for round 1; the titles and the scroll
reset and restore stay. Read "Round 2" first.

## Findings

- S1-002, Medium (with S2-003, S2-013, S3-001, S4-004, S4-020, S5-017, J6-011, J6-002, J6-003): every static
  page had the title "Credit OS", and a route change moved no focus, announced nothing and kept the scroll
  offset of `main` (focus fell to the body when the link that held it was removed).

Cause: `web/index.html` held the only title and `App` never set one; `main` is the one scroller and is
never remounted, so a route change kept its offset and left focus on a removed link (`App.tsx`).

## What changed

- `web/src/pages/route-table.ts`: `Route` gains an optional `subject(params, data)`: what the page is
  about, for its document title. No existing route or test needs it.
- `web/src/pages/library/routes.tsx`: library routes give a subject: the issuer for the history; for run
  pages the issuer and the run's date (`head.asOf`); for Modules the module's name first (the run's first
  module on the index form); for each Evidence route the tab ("Summary", "Trace", "Sources", "Gaps",
  "Record"). A run or issuer the library lacks gives none.
- `web/src/pages/model/routes.tsx`: the six run pages give the issuer name and the run's date
  (`header.issuerName`, `header.asOf`) read from the model slice.
- `web/src/App.tsx`:
  - `pageTitle` builds `<page> — <subject> — Credit OS` for the page `Page` draws (the kit, Page not found
    and the library placeholder have their own names); `App` sets `document.title` from it.
  - `useRouteChange`, on every route change after the first load:
    - scroll: `main` goes to the top, or, on Back and Forward, to the offset that history entry was left
      at. Entries are named by a key `App` writes into `history.state` (`replaceState` with no URL, so no
      new entry and no `hashchange`), and the offsets are kept in memory; a page followed a second time
      opens at its top, because a followed link is a new entry with no key;
    - focus: stays where the new page put it (the Trace and Gaps item pages focus their row in their own
      effect, which runs after the reset); else goes to the link the reader used when the new page draws it
      again as the current page (a run tab, an Evidence tab, a module in the navigator), so the next Tab is
      the next tab; else to `main`. Focus is placed with `preventScroll`, so a module far down a long
      navigator does not carry `main` away from the new page's name;
    - a polite, atomic, visually hidden live region (`<p aria-live="polite">`, drawn once by `App`) gets
      the new title, so a screen reader says where the reader is.
  - The first load moves no focus and announces nothing.
- `web/src/shell/Shell.tsx`, `web/src/pages/library/Evidence.tsx`, `EvidenceFrame.tsx`, `Module.tsx`,
  `parts/ModuleNav.tsx`: not changed. The route-level rule above fixes their symptoms (remounted frames and
  navigators) without keeping them mounted. `Shell` is also the connected app's frame, so the behaviour
  stays in `App`, which only the static app uses.

  address, Model index and run pages, run start and activity, the kit, an unknown address), the page name

  each move focus to `main` and say the new title; the item row keeps the focus the page gave it; the run

  focus is placed with `preventScroll`; the Library breadcrumb, not drawn again, falls back to `main`;

- Scroll: a followed page opens at 0; Back and Forward return to the offset each page was left at; a page
  followed a second time opens at 0.
