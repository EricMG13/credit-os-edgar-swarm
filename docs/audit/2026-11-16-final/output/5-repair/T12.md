# T12: Synthetic proof: documented steps complete a run; a refused module is reported as such

## Cause

**B0-003 / J1-014.** `docs/react-workflow.md` "Open the interface" named two buttons that do not
exist ("Review inputs", "Approve summary"), left out Your name (the review sheet is not reached
without it), and never uploaded `proof/northbridge-credit-agreement.txt` or set Legal documents to
Executed agreement. A run that followed the text declared no legal documents.

**J1-002.** The failure is not the scheduler, the engine or the review sheet reporting a refusal
wrongly. It is the synthetic launcher:

1. A run that declares no legal documents (`attachments.legal_documents == "none"`, the form's
   default "No agreement") makes the engine hold CP-4 to its source gate
   (`src/deploy_workflow/owners/cpos_launch.py` `_source_gate_issues`, from the live run of
   2026-11-16). CP-4's instructions carry `_SOURCE_GATE` up front, so a model writes a blocked
   handoff (`module_status: Blocked`, a Bottom line beginning `Not assessable: `) and the run
   goes on. The engine's own tests pin both sides:
   `test_a_run_with_a_blocked_cp4_delivers_cp3s_capital_structure` (exit 0, CP-4 called once) and
   `test_a_cp4_written_without_an_agreement_is_still_refused` (a filled CP-4 is refused three
   times and the run stops).
2. `proof/launcher.py` answers every request for a module with that module's one fixed canned
   handoff (`proof/handoffs/CP-4.md`, written as if an agreement existed). It ignores the checker's
   rejection, so CP-4 is rejected three times (three "Module draft rejected." events) and the run
   stops with `cpos_live_not_accepted: CP-4 not accepted within bounds`, which
   `src/deploy_workflow/run_events.py` `stop_reason` reduces to "checker" and
   `src/deploy_workflow/inbox/runs.py:352` shows as "stopped: checker".
3. A second consequence of the same gate: with no legal documents the engine routes the report's
   Capital structure to CP-3 (`cpos_launch._layout`), and the canned CP-3 handoff has no such
   section ("The report adapter refused this handoff: markdown_selector: expected one
   CP-3/Capital structure/None"). Blocking CP-4 alone moved the failure to CP-3.

So the synthetic launcher is the cause, and it is in T12's file list. No file outside the list
is needed to make an accepted Will refuse limit end in a finished run. One residual is outside it:
see `NEEDS FILE` below.

## Doubts traced

- A context declaring `draft`: `no_legal_documents` is false, so CP-4 keeps the canned handoff, as
  before (the engine's checker does not gate `draft`). Unchanged.
- An agreement uploaded while Legal documents is `none`: `verify_upload` accepts the file, the
  engine still gates CP-4, so the launcher blocks it, as the engine requires.
- The gate decision uses the engine's own `no_legal_documents(load_context(...))`, so the launcher
  and the checker cannot disagree. Routed CP-4 selectors are not written: in `credit_snapshot`, the
  only pathway the launcher accepts, a gated CP-4 owns none (the test would fail loudly if that
  changed).
- `findings.replace("\n## Calculations", ...)` inserts the CP-3 section once; a missing anchor
  would leave the section out and the engine's selector check would refuse the run, not hide it.
- Not a presentation change: no fidelity entry is needed beyond the note below.
