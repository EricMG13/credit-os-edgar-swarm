## Decisions

- Scroll and focus (C3-002, C3-003, C4-034, J3-001): one hook in the reader (`ReportLibrary.tsx`), not per link, because the cause is the shared `main` scroller that no report address change resets. A new address opens at the top. Focus goes to the page's first `h2` only when the control that had it is gone (focus on the body), so a tab link that kept focus keeps it (C3-002 recorded that behaviour as fine) and a keyboard user who activated a navigator link, a module link in Forecast or the Module select lands on the new page's heading. The Navigator stays keyed per module; the heading takes focus after the remount, which the finding allows ("or moves to the new module's heading").
- Back and Forward: each history entry is named in `history.state` (`reportEntry`) the first time the reader sees it; the offset read from `main`'s scroll events is kept in memory per entry and restored when the reader returns to an entry. After a reload the names survive but the offsets do not, so such an entry opens at its top. No focus move on Back, because focusing a heading above the restored position would send the next Tab back to the top.
- Module select (C3-004, C5-006): a native select kept (the probes use the `combobox` role and `select`), with an explicit button instead of navigating on change. A pointer or touch user now chooses and then presses Open module (Modules, below 1001 px) or Apply filter (Evidence, all widths): one extra step, which the finding's own suggestion ("a Go button") accepts. Detecting arrow keys to hold only keyboard changes was rejected: browsers differ on whether a keydown precedes a change from an open list. The button is disabled while the choice equals what is on the page. One commit makes one history entry, so Back needs one press. This changes what the user controls; if the owner prefers one-step pointer selection, the alternative is the kit Select, which these probes cannot drive.
- On this page (C3-005): the entry takes the section's own title (`drawingTitle(heading)`), so "Key findings" appears only where the module wrote Key findings. Financial foundation now lists "Financials and credit metrics". The entry's icon is the section's own too (records, not the key-findings icon).
- Fidelity (AGENTS.md presentation check, scope: connected Modules, Evidence and report-address changes only): no value, period, unit, source or limitation on any page was touched. What the reader sees differs in the Navigator label of one section on modules with no Key findings, the Module select controls, and where the page is scrolled and focused after an address change. For the coordinator's VERIFICATION.md entry.

Not verified: the order of the figures against the prose (C3-028, blocked). Touch behaviour of the native Module picker on a phone (only 390 px in desktop Chromium was driven). Screen-reader announcement of the focused heading (focus placement was checked with `document.activeElement` only). Back restore when a page's content grows after the first paint (the Forecast and Modules pages of the synthetic run were complete at restore time; a page that gains height later would clamp the offset). Firefox and Safari (only the headless Chromium shell was available). `ConnectedApp.test.tsx` first ran under CPU load from the concurrent probe run and timed out in four tests; run alone it passed (185 of 185).
