## Decisions

- C3-028 (OQ-02, binding): the controller added `ReportContent.tsx` to T14 for this finding, because it is a group 2 file, the tasks that use it later (T16, T18, T22) run after T14 in tasks.md order, and no running task touches it. The first report listed it as Blocked; that part is now done. `ReportFindings` gets an optional `beforeLimitations` node. `findingsLayout` records where it goes: immediately before the Limitations passage or its gap panel, and, for a module with neither (a bottom-line-only data module, a blocked module), after its last passage group and before the other sections. `EmptyFindings` draws it too, so a handoff with no sections still shows its figures. Overview passes only `afterBottomLine`, and Changes neither, so their order is unchanged (the callers are `ReportLibrary.tsx`, `Changes.tsx` and `Modules.tsx`; `Forecast.tsx` does not use `ReportFindings`). `Modules.tsx` keeps the confidence tile and the headline tiles under the Bottom line and passes the `#module-figures` block as the new prop; the navigator inserts "Figures and records" after the last Bottom line, Key findings or Contrary evidence entry. The simpler alternative, the whole figures block after all of `ReportFindings`, would have put it after Limitations and the records card, against the ruling.
- C3-004 and C5-006: the Open module and Apply filter buttons are the finding's own repair, not an R5 change. The register's suggested change for C3-004 is "Navigate on commit (a Go button, or on blur or Enter)". A native select is kept (the probes use the `combobox` role and `select`), and a button commits the choice: Open module on the Modules page below 1001 px, Apply filter on Evidence at all widths. A pointer or touch user takes one extra step. Detecting arrow keys to hold only keyboard changes was rejected: browsers differ on whether a keydown precedes a change from an open list. The button is disabled while the choice equals what is on the page, and one commit makes one history entry, so Back needs one press.
- Scroll and focus (C3-002, C3-003, C4-034, J3-001): one hook in the reader (`ReportLibrary.tsx`), not per link, because the cause is the shared `main` scroller that no report address change resets. A new address opens at the top. Focus goes to the page's first `h2` only when the control that had it is gone (focus on the body), so a tab link that kept focus keeps it (C3-002 recorded that behaviour as fine) and a keyboard user who activated a navigator link, a module link in Forecast or the Module select lands on the new page's heading. The Navigator stays keyed per module; the heading takes focus after the remount, which the finding allows ("or moves to the new module's heading").
- Back and Forward: each history entry is named in `history.state` (`reportEntry`) the first time the reader sees it; the offset read from `main`'s scroll events is kept in memory per entry and restored when the reader returns to an entry. After a reload the names survive but the offsets do not, so such an entry opens at its top. No focus move on Back, because focusing a heading above the restored position would send the next Tab back to the top.
- On this page (C3-005): the entry takes the section's own title (`drawingTitle(heading)`), so "Key findings" appears only where the module wrote Key findings. Financial foundation now lists "Financials and credit metrics". The entry's icon is the section's own too (records, not the key-findings icon).
- Fidelity (AGENTS.md presentation check, scope: connected Modules, Evidence and report-address changes only): no value, period, unit, source or limitation on any page was touched. What the reader sees differs in the Navigator label of one section on modules with no Key findings, the Module select controls, where the page is scrolled and focused after an address change, and the position of the figures block on a module page (now after Contrary evidence, before Limitations; the block's own content is unchanged). For the coordinator's VERIFICATION.md entry.
