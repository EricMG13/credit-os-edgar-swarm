# T32 (group 3): Issuer history draws its runs

Base: `0143a3e` (audit/repair-3). Implementer: repair-3 worker for T32.

## Findings

- S2-001 (Medium; merged J6-006, Medium): an issuer's history page drew none of its runs when the issuer
  had no readable report, although its subtitle counted them ("Report history: two runs since June 2026")
  and its home card described a run (Running, Finished, Failed, Capped). Seen on Corvane Packaging,
  Tessaly Foods, Ardenne Cable and Lumora Health (0 of 2, 1, 2 and 1 rows drawn).

Cause: `History` in `web/src/pages/library/History.tsx` returned `NoReport` whenever `history.empty` was
set and never called `RunFeed`, so every entry of such an issuer was dropped.

## Repair

- `web/src/pages/library/History.tsx`: `NoReport` draws `RunFeed` for the issuer's entries below the
  "No report yet" state and its two buttons, when `history.entries` is not empty. With no entries it
  draws no list. The doc comment of `History` says so. The empty state, its sentence, the subtitle and the
  entries' own text are unchanged; no "Open latest report" button is drawn (there is no latest run), and
  no row carries a report link (every such entry has `report: null`).
- `web/src/pages/library/parts/RunFeed.tsx`: no change needed (listed in the task; it is reused as is).

This is the first of the finding's two suggestions (draw the entries under the state); the second (drop
the count from the subtitle) would remove information the reader sees (R5).

## Test (failing first, then passing)

- `web/src/pages/library/History.runs.test.tsx` (new): on the real history route with the fixture's own
  data, for each of the five issuers with `history.empty` set (the four carded issuers and Corvane
  Fasteners) the page draws one row per entry, in order, with "Run as of", "Ran", state, pathway and
  sentence and no link in it; Tessaly Foods keeps its h2 "No report yet", both buttons, the subtitle and
  no "Open latest report" / "Open report", with the list after the state; an issuer with `empty` set and
  no entries draws the state and no list.
  Before the repair: 6 of 8 failed (`Unable to find an accessible element with the role "list"`; the
  five per-issuer rows and the order test; the roster test and the no-entries test passed because they
  assert what was already true). After: 8 of 8 pass.

## Existing test changed

- `web/src/pages/library/History.test.tsx`, "an issuer with no report yet" (Corvane Fasteners): it
