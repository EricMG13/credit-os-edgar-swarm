# T26 (group 3): Static Start a run and New run open the run start

Base: `99ceeed` (audit/repair-3). Implementer: repair-3 worker for T26.

## Findings

- S1-001 (High; merged J6-005, Medium): the library's "Start a run" and "New run" buttons opened Run
  activity, a saved running example of another issuer, not the run start page.

Cause: `RUN_START` in `web/src/pages/library/parts/links.ts` was `"#/run"`, the group's bare address,
which draws the run group's home route, `/run/activity`. The run group had no address that starts a run
without naming a draft id, so no library link could point at the start page without hard-coding a draft
the data may not hold.

## Repair

- `web/src/pages/run/routes.tsx`: a new route `/run/start` (title "Start a run", no home) beside
  `/run/start/:draft`. It draws `StartPage` for the first draft of the run slice, which the slice reader
  already requires to be the documents step ("a new run starts from the first draft"). The draft id is
  read from the slice, not written into a link. With no run slice, or no drafts, `StartPage`'s own
  states ("No run data in this library", "No draft has this address") show under the same title.
- `web/src/pages/library/parts/links.ts`: `RUN_START` is `"#/run/start"`; its comment says what it opens.

`Home.tsx` and `History.tsx` needed no change: both, and `RunFrame.tsx`, take the address from
`RUN_START`. The rail's "Run" item still opens Run activity (`#/run`), unchanged.
