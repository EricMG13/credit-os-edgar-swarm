## What changed

- `web/src/pages/run/start/Purpose.tsx` (S6-001): the focus-visible branch of the radio card now reads
  `outline-2 outline-solid outline-offset-2 outline-brand`. Tailwind's `outline-2` sets a width only and the
  card also carries `outline-none`, so the outline style stayed `none` and nothing was painted. `outline-solid`
  replaces `outline-none` (same class group in `cx`) only while focus is visible. `PurposeCards` is also what
  the connected app's Start page draws, so it gets the same ring.
- `web/src/pages/run/activity/ActivityPage.tsx` (S6-010): the two identical label rows (a readable and an
  unreadable run) now share a small `Labels` component. Each chip passes
  `size-auto max-w-full rounded-2xl whitespace-normal wrap-anywhere` to the Badge, which `cx` (tailwind-merge)
  merges over the Badge's own `size-max` and `whitespace-nowrap`. `size-auto` is needed as well as the wrap
  classes: with `size-max` (width max-content) the chip's min-content contribution stays the whole unbroken
  label, so the header's left column still widened and Stop run stayed at x = 1679 (first attempt, probe still
  exit 1). `rounded-2xl` is a pill on one line and a bounded corner on several, so a wrapped label does not
  have its corners cut by `rounded-full`.
- `web/src/components/base/badges/badges.tsx`: unchanged. The nowrap is the Badge's default and the label row
  can override it through `className`, which is where the finding's own suggested change puts it ("the change
  belongs in the label row"). Every other user of `Badge`/`BadgeWithDot` (about 33 files: Signal, library,
  model, connected, StatusBadge, Withheld, tabs, Kit) therefore draws exactly as before; the new test checks
  the default Badge and the run state chip still carry `whitespace-nowrap`.

  kit file outside the list, so the title is found from a ref on the panel's own wrapper. T25's saved-example
  wording is untouched. React Aria's restore-focus step only acts when focus is on the body, so it does not
  take focus back from the title.

### S6-007: the Runs breadcrumb opens an index of the slice's runs

- `web/src/pages/run/routes.tsx`: new route `path: "/run/runs"`, `title: "Runs"`, no `home`, padded layout
  (the shell draws the title as the one h1 and the design-reference note, as on the Start pages). It matches no
  other run pattern (different literal and depth). The bare `#/run` and `#/run/activity` still draw the current
  run and `/run/start` is unchanged.
- `web/src/pages/run/activity/ActivityPage.tsx`: the Runs breadcrumb now links to `#/run/runs`; new exported
  `RunsIndex` (in this file, as no new source file may be added). It lists every `run` and `unreadable` record
  the slice holds, in slice order, in groups `In progress` (state Running), `Queue` (Queued), `Ended` (Finished,
  Failed, Capped, Rejected, Interrupted) and, because an unreadable record's state is not known, `State not
  known`; an empty group is not drawn. A row is a link to the run's activity page (issuer), the state badge
  for the Ended group only (a group whose heading is the state draws none), the run's labels (the slice keeps
  the pathway and the as-of in `labels`: "Full credit review", "As of Q3 FY2026"), and the run's own
  `elapsed.note` ("Started today at 14:38", "Finished today at 15:16"); the note is the slice's own field and
  is what tells apart runs whose issuer and labels are equal. Record kind `none` is not a run and is not listed.
  Empty states: no listed run draws "No runs yet" (the library page's own words) with the existing
  "Nothing is running..." sentence, now a shared constant `NOTHING_STARTED`, and Start a run when a draft
  exists; a missing slice draws "No run data in this library". The index adds no wording about a run.
- The other option (dropping the breadcrumb word) was not taken: README R5.
