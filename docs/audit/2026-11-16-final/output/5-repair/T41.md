## What changed

- `web/src/pages/run/start/Purpose.tsx` (S6-001): the focus-visible branch of the radio card now reads
  `outline-2 outline-solid outline-offset-2 outline-brand`. Tailwind's `outline-2` sets a width only and the
  card also carries `outline-none`, so the outline style stayed `none` and nothing was painted. `outline-solid`
  replaces `outline-none` (same class group in `cx`) only while focus is visible. `PurposeCards` is also what
  the connected app's Start page draws, so it gets the same ring.
- `web/src/pages/run/activity/ActivityPage.tsx` (S6-010): the two identical label rows (a readable and an
  unreadable run) now share a small `Labels` component. Each chip passes
  `size-auto max-w-full rounded-2xl whitespace-normal wrap-anywhere` to the Badge, which `cx` (tailwind-merge)
  merges over the Badge's own `size-max` and `whitespace-nowrap`. `size-auto` is needed as well as the wrap
  classes: with `size-max` (width max-content) the chip's min-content contribution stays the whole unbroken
  label, so the header's left column still widened and Stop run stayed at x = 1679 (first attempt, probe still
  exit 1). `rounded-2xl` is a pill on one line and a bounded corner on several, so a wrapped label does not
  have its corners cut by `rounded-full`.
- `web/src/components/base/badges/badges.tsx`: unchanged. The nowrap is the Badge's default and the label row
  can override it through `className`, which is where the finding's own suggested change puts it ("the change
  belongs in the label row"). Every other user of `Badge`/`BadgeWithDot` (about 33 files: Signal, library,
  model, connected, StatusBadge, Withheld, tabs, Kit) therefore draws exactly as before; the new test checks
  the default Badge and the run state chip still carry `whitespace-nowrap`.

## Blocked (needs a file outside the task's list)

- S6-002: the Submit button is unmounted when Confirm moves the hash to the Started step, so focus can only
  be put on the new panel once it exists. In `Start.tsx` that needs a timer, frame callback or an observer on
  the document, and `Start.test.tsx` ("the run pages reach no service, storage or timer") bans `setTimeout`,
  `requestAnimationFrame` and similar words in every non-test source under `web/src/pages/run`; that test may
  not be loosened. The timer-free repair is in `web/src/pages/run/start/Started.tsx`: on mount, focus the
  Run started panel's first link (or give the alert title `tabIndex={-1}` and focus it) from an effect, so
  focus lands there whatever opened the page. The status panel is also drawn together with the page, so a
  screen reader is only told through the focus move. `Started.tsx` was T25's file and is not in T41's list.
- S6-007: the probe needs a link named "Runs" in the breadcrumb that opens a page without the word "Running"
  in `main` (it reads the destination's text), so the repair is an index of the slice's runs, not a removed
  link (removing it makes the probe time out). That needs a new route (`web/src/pages/run/routes.tsx`: the
  bare `#/run` and `#/run/activity` addresses are the Run rail item's landing on the current run) and a new
  page component. One existing test asserts the Runs link's `href` is `#/run`
  (`ActivityMore.test.tsx` line 142) and would change with it. If
  the index groups runs by headings "In progress", "Queued" and "Ended" (CM-090's own words) and shows the state
  word only for ended runs, the probe's text check would also pass. This is a design decision for the
  controller (address of the index, whether the running rows carry a state badge).
