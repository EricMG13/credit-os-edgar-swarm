## Decisions

- C3-006/C5-026: reworded at the source (`credit_os_chips.py`), not in the web. The chips are recomputed
  from stored handoffs on every snapshot, so older runs are fixed as well; the Evidence page and the
  drawer both read the note unrewritten, so one change covers both. The two alias notes
  (`... marked alternate in CP-0`, `CP-0 roles leave ...`) have the same cause and reach the same
  drawer, so they got the same name (`Source readiness`). `sourceFiles.ts` and `ReportContent.tsx` are unchanged.
- C5-008: the handoff's level-1 title is the module's code and the card already names the module, so
  a title-only level-1 section is not drawn. A level-1 section that holds text keeps its text under the
  module's name. Nothing else on the Evidence page moved.
- C4-001, delivery text (`cpos_forecast.py`): `Python's arithmetic` -> `arithmetic`; `the CP-2G handoff` ->
  `the Forward credit model`; `the CP-1 handoff ... the financial foundation's own figures` -> `Financial foundation
  ... its own figures`; `Python divided each by 1,000` -> `each was divided by 1,000`; the facility limit
  names the Forward credit model. Every qualification is kept (inputs, not arithmetic, unreviewed; not analytical
  review; the scale and its divisor). The module names are written out, not imported: `cpos_forecast`
  sits below `credit_os_chips` in the import layers (`.importlinter`), and a test compares the two names with
  `MODULE_NAMES`.
- C4-001, module codes inside stored model text (`CP-1 prints ...`, `latest period CP-1 labels`) are
  drawn through `readerText` on the Forecast page (notes, limits, qualifications, cell reasons, case
  descriptions, the other-grid column group, the basis limitation, the assumptions intro, chart gaps,
  calendar gap reasons). That covers `cpos_periods.py` and `cashflow.py` sentences without editing files
  outside the list, and runs published before this change. A run delivered earlier still holds
  `Python's arithmetic` in its stored `forecast_exact.json`; it is not rewritten.
- C4-001, chart gaps (`RunCharts.tsx`): a gap reason that cites a page (`p.12`) is drawn as `See Evidence.`
  (the reason is not dropped: the figure's Source table link stays); otherwise a module code in it is
  drawn as the module's name. The probe's stored state `see Filing p.12 ... (CP-4)` requires the first rule.
- C4-001 wording: button `Open the forward credit handoff` -> `Open the model evidence` (the
  register's suggestion); sentence `The handoff gives` -> `The Forward credit model gives`; trace name
  `Handoff free cash flow` -> `Forward credit model free cash flow`; `Sent back by the build.` ->
  `The chart data did not fit the required table form, so no chart is drawn.`;
  Calendar `The handoff records a date gap in Evidence.` -> `A date gap is recorded in Evidence.`.
- Shorthand (J3-005): the sentence listing columns with no values spells out YTD, PYTD, LTM, Prior LTM
  and PF LTM; the table header keeps the stored label beneath its spelled-out group heading (`Last twelve
  months`, `Pro forma`). `n.m.` is defined by the model note drawn on the page. No new key was added.
- Visible consequence to note for T18: the scope panel at the top of Forecast drew only the fragment
  `Not analytical review.` before, because the first sentence of the limit held a module code and
  `scopePassages` drops such a sentence. Now that the sentence is clean it is drawn whole there as well
  as under Model limitations, so the same qualification appears twice, which is C4-002's subject.
  Nothing is removed; the qualification is now complete in the scope panel.
