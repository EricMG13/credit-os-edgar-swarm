# T01b: an OSError's kind, never its path, in source warnings and the rebuild note (R1-007, R1-008)

Findings R1-007 and R1-008 (both High; a leaked path is always repaired, R3), ruling L10 (lead, 2026-11-17).

BASE (starting commit, used for the quality gate): `d7b1e66f91714ad84d4edc2391e66d38297fd8d8`

## Findings

- R1-007. `react_frontend/sources.py` stored `str(error)` of an `OSError` as the source's problem
  (`_load_source`, line 232) and as the workflow-pin problem (`verified`, line 247, re-raised as a `Refused`
  and stored at line 256). The operating system's text is `[Errno 13] Permission denied: '<absolute path>'`, so
  the absolute server path reached `/connected/snapshot` (scoped and unscoped) at
  `workspace.runs.*.evidence.sources[].sourceWarning`, which `Evidence.tsx:455` draws, and the same text is the
  citation chip's `reason` (`Checked.cache` is also handed to `native.Pages`).
- R1-008. `Scheduler._rebuild` passed `f"{error}"` into the held note `the library could not be rebuilt (<error>);
  ended runs wait for it`. `/activity.js` serves `_engine/activity.js` as written (`run_start/service.py:256`,
  inherited by `react_frontend`), so an unreadable pinned context, `workflow.json` or `instructions/*.md` put the
  errno text and the absolute path on the wire. T03 had already mapped the note to a plain sentence for
  `/connected/activity`; the raw route was not covered.

## What changed

Two production files, one choke point each; nothing else.

1. `react_frontend/sources.py` (the source problem text only): new `_problem(error, relative)`. A refusal
   (`ValueError`, including `Refused` and `SourceMismatch`) keeps its own words, which already name only the name
   inside the run; an `OSError` becomes `<relative> could not be read (<kind>)`, kind = `type(error).__name__`.
   `_load_source` passes `<folder>/inputs/<digest>`, `verified` passes `<folder>/workflow.json`, the same run-relative
   names `read_inside` uses in its own refusals (`<relative> is missing`). Example:
   `20261117-101533-01/inputs/c92a94e6...fe2c could not be read (PermissionError)`. The chip `reason` for the same
   source now carries the same sentence, since it is the same cache entry.
2. `src/deploy_workflow/inbox/scheduler.py` (the rebuild note only): `_rebuild` hands `_rebuild_failed` the error's
   kind (`type(error).__name__`) for the page note; the log text (`library rebuild failed: {error}`) and
   `logger.exception` are unchanged, so `watcher.log` keeps the full error and the once-per-distinct-error log
   deduplication is unchanged. The fixed `update_library.py not found` note is unchanged. One docstring sentence
   says why the argument is the kind only.

`react_frontend/run_activity.py` is untouched: its rebuild-note pattern
(`the library could not be rebuilt \(.*?\); ended runs wait for it`) matches the new text, and the scratch check
below shows `/connected/activity` still sends T03's plain sentence.
