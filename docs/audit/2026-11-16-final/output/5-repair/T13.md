## Decisions

1. **C4-028: read the decimal comma, do not reject it.** The task title says "read a decimal comma
   correctly" and the ruling note calls it "an ordinary input" (R3), so `3,75` is drawn as 3.75, not removed
   from the chart as the finding's suggested change would do (the suggestion is not a requirement). Grammar
   in `amount()`: comma groups of exactly three digits after a first group of one to three digits not starting
   with 0 are thousands (`1,250`, `12,345,678`, `1,250.5`, unchanged); any other single comma between digits
   is a decimal comma (`3,75`, `12,5`, `0,375`, `1234,5`); every other placement (`1,2,3`, `1,23,456`,
   `1.234,56`, `1,`, `,5`) is not a number and is not plotted (the chart falls back to its source table, as
   for any unreadable cell). The published label stays exactly as written (`3,75`; module-written text is not
   rewritten); only the position uses the reading. A residual ambiguity remains by design: `3,750` is read as
   3750 (the grouping the handoffs already use, for example `1,250`), never as 3.750. All callers of `amount`
   (`charts.tsx`, `PortfolioLimits.tsx`, `LegacyForecast.tsx`, `report/Changes|Securities|Forecast|Downside|MacroSensitivity`)
   get the same grammar; their tests pass. A variant that rejects `3,75` made the C4-028 probe exit 2 (no
   figure to measure once the chart falls back to the table), checked in a scratch worktree that was removed.
2. **C3-029: a column, kept in `chartTable`, not a caption.** `chartTable` returns only `head` and rows, so
   the limitation is kept as the existing `Basis and limitation` column (the same column the plain tables on
   the page print) and only `Source` and `Evidence` stay with the trace drawer. A caller that names its
   own `columns` is not overridden: `ColumnsChart` throws unless the table columns after the first equal the
   series names, so appending the column inside `chartTable` broke 9 existing tests (tried, reverted).
3. **A limitation that itself names a file, hash, register id or module code** is shown in the drawer only;
   the Table form cell reads `Qualification recorded in Evidence.` (the wording `ChartQualifications` already
   uses) and only while the sources are in the drawer. This follows the voice standard (references live on
   Evidence and in the drawer) and the plain tables, which replace such a cell with an `In Evidence` link.
   On the Evidence page (`evidenceInDrawer` false) every column is shown unchanged.
4. No module-written text, value, period or unit changed; the Table form only gains published columns.
5. **The controller added `charts.tsx` `periods()` to T13** (controller decision, after the first report named
   the blocker). Only the `ColumnsChart` branch of `periods()` changed: it now also passes
   `detailTable={chartTable(table)}`, as `paired`, `recovery` and `stack` already do. The Table form shows
   `detailTable ?? table`, so it carries the full published row (Reporting unit, Basis and limitation) while the
   chart and its text alternative keep the series-matched `table`. No import added; the imports and `stack()`
   (T19's regions) are untouched. The Table form of these six charts therefore also gains the `Reporting
   unit` column (CM-025 lists the unit with the basis); the chart itself is unchanged.
