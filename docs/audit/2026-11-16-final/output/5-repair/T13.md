## Decisions

1. **C4-028: read the decimal comma, do not reject it.** The task title says "read a decimal comma
   correctly" and the ruling note calls it "an ordinary input" (R3), so `3,75` is drawn as 3.75, not removed
   from the chart as the finding's suggested change would do (the suggestion is not a requirement). Grammar
   in `amount()`: comma groups of exactly three digits after a first group of one to three digits not starting
   with 0 are thousands (`1,250`, `12,345,678`, `1,250.5`, unchanged); any other single comma between digits
   is a decimal comma (`3,75`, `12,5`, `0,375`, `1234,5`); every other placement (`1,2,3`, `1,23,456`,
   `1.234,56`, `1,`, `,5`) is not a number and is not plotted (the chart falls back to its source table, as
   for any unreadable cell). The published label stays exactly as written (`3,75`; module-written text is not
   rewritten); only the position uses the reading. A residual ambiguity remains by design: `3,750` is read as
   3750 (the grouping the handoffs already use, for example `1,250`), never as 3.750. All callers of `amount`
   (`charts.tsx`, `PortfolioLimits.tsx`, `LegacyForecast.tsx`, `report/Changes|Securities|Forecast|Downside|MacroSensitivity`)
   get the same grammar; their tests pass. A variant that rejects `3,75` made the C4-028 probe exit 2 (no
   figure to measure once the chart falls back to the table), checked in a scratch worktree that was removed.
2. **C3-029: a column, kept in `chartTable`, not a caption.** `chartTable` returns only `head` and rows, so
   the limitation is kept as the existing `Basis and limitation` column (the same column the plain tables on
   the page print) and only `Source` and `Evidence` stay with the trace drawer. A caller that names its
   own `columns` is not overridden: `ColumnsChart` throws unless the table columns after the first equal the
   series names, so appending the column inside `chartTable` broke 9 existing tests (tried, reverted).
3. **A limitation that itself names a file, hash, register id or module code** is shown in the drawer only;
   the Table form cell reads `Qualification recorded in Evidence.` (the wording `ChartQualifications` already
   uses) and only while the sources are in the drawer. This follows the voice standard (references live on
   Evidence and in the drawer) and the plain tables, which replace such a cell with an `In Evidence` link.
   On the Evidence page (`evidenceInDrawer` false) every column is shown unchanged.
4. No module-written text, value, period or unit changed; the Table form only gains published columns.
5. **The controller added `charts.tsx` `periods()` to T13** (controller decision, after the first report named
   the blocker). Only the `ColumnsChart` branch of `periods()` changed: it now also passes
   `detailTable={chartTable(table)}`, as `paired`, `recovery` and `stack` already do. The Table form shows
   `detailTable ?? table`, so it carries the full published row (Reporting unit, Basis and limitation) while the
   chart and its text alternative keep the series-matched `table`. No import added; the imports and `stack()`
   (T19's regions) are untouched. The Table form of these six charts therefore also gains the `Reporting
   unit` column (CM-025 lists the unit with the basis); the chart itself is unchanged.

### Decisions

1. **Issue 1: the column's evidence, kept as data of the table.** A cell is evidence of the decimal comma when it holds one comma
   that cannot group thousands (`3,75`, `12,5`, `0,375`, `1234,5`, `1,2345`). `decimalCommaColumns(rows)` finds those columns
   once, in `publishedTables`, and the table carries them (`SourceTable.decimalComma`). `cellAmount(table, row, column)` reads a
   cell with its column's convention: in such a column one comma and exactly three digits (`2,800`) is a decimal comma, 2.8.
   Everything else is read as before: two or more comma groups (`1,250,000`, `12,345,678`, Indian `21,00,000`) and a comma with a
   point (`2,800.5`) are never decimal; `1.234,56`, `1,2,3`, `3,` stay refused. A column with no evidence reads as before. A column
   written only in three-decimal commas (`3,750 / 2,800 / 3,000 / 2,250`) proves nothing: it is read as thousands, as the round 1
   Decisions 1 say, and measured (axis to 4,000, bars 3750 and 2800).
   Checked by enumeration (a throwaway script outside the repository, old and new grammar side by side): over 5,380,839 strings of up to
   7 characters from `0 1 2 5 9 , . - space`, and 12,207,030 strings of up to 10 characters from `0 1 2 , .`, the new reading refuses
   exactly what `5a209d5` refuses, with or without the evidence flag (0 differences in null-ness, except the Indian forms of
   decision 3); with no evidence it gives the value `5a209d5` gives (0 differences); with evidence the value differs only for
   `[1-9]\d{0,2},\d{3}` (18,500 strings in the first set, 702 in the second), always by a factor of 1,000. Nothing `5a209d5` refuses is
   newly drawn except the Indian forms of Decision 3, which the base drew (3,402 strings in the second set, 0 in the first, whose strings are too
   short); and nothing it read correctly in a column with no evidence changes.
2. **Where the evidence is used.** `amount(cell)` keeps its one-argument signature: a second parameter was tried first and
   `tsc` rejected it, because `charts.tsx` maps `amount` over cells (`cells.map(amount)` in `paired` and `texts.map(amount)` in
   `recovery`), which would pass the array index as the flag. The reading with the column is the new `cellAmount`. It is wired in
   `periods()` only (Leverage, Interest cover, Liquidity, Debt maturities, Revenue and EBITDA, Refinancing need, the Review 2 case).
   `chartCells` and `unitsMatch` only test whether a cell is a number, which the column reading never changes, so they stay.
   **Open, not changed: the other seven chart kinds still read per cell** (waterfall, paired and dumbbell, range, scatter, stack,
   bullet, recovery), so a `3,75` and `2,800` column in one of them is still drawn with `2,800` at 2800. Each is a one-line change in
   `charts.tsx` outside `periods()` (stack is T19's): `amount(row[c] ?? "")` becomes `cellAmount(table, row, c)` at lines 51 (`valuesIn`), 145, 206, 216, 217,
   228 (`cells.map(amount)`), 275, 276, 278, 313, 365, 431, 432 and 478 (`texts.map(amount)`); line 145 is the bridge. Not done
   because the brief limits `charts.tsx` to `periods()`; the controller should assign it (the evidence and the reader exist).
   `Changes.tsx`, `PortfolioLimits.tsx`, `LegacyForecast.tsx` and the report pages read single cells without a table and are unchanged.
3. **Issue 4: Indian grouping is kept at its value.** `COMMA_GROUPS` now also accepts a last group of three after one or more pairs
   of two, behind a first group of one or two digits not starting with 0 (`1,23,456`, `21,00,000`, `1,23,45,678`, optional `.d`).
   Those forms were read at that value on the base and were refused at `5a209d5`; the enumeration shows they read to exactly the value
