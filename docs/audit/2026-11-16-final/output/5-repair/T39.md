## Cause

- S4-006: the filter's state lived in `FilteredTab`, which `Evidence.tsx` drew only for Sources, Trace and Gaps and
  keyed by the tab, so each tab started at All and Summary and Record had no filter.
- S4-008: `EvidenceRecord.tsx` drew the delivered table as it came, including its `Code` column (the fixture's
  `calls.columns[1]` and each row's first cell).
- S4-009: the same component drew the four delivered rows and the run's delivered Total row with no word that the
  rows are some of the run's modules.

## What changed

- `web/src/pages/library/Evidence.tsx` (S4-006): `FilteredTab` is replaced by `EvidencePages`, one component inside
  the run's frame that calls `useModuleFilter` once and draws one `EvidenceFrame` with the filter for all five tabs.
  The app draws a route at one place, so this component stays while the tab changes and the choice stays; the run's
  frame already keys the page by run, so a run starts at All. Each tab applies the chosen module:
  - Sources, Trace, Gaps: as before (rows narrowed, empty state with its way back).
  - Record: see below.
  - Summary: with a module chosen, the three count tiles show that module's counts, counted from the rows the three
    tabs draw for it: "Source files read" (files the module read, ids compared across the avatars and the "+N"),
    "Traced items" (Trace rows with its id), "Gaps" (Gap rows with its id), each with the note "By <module>" or
    "In <module>"; a module with none shows a real 0. The delivered tiles carry notes ("7 read in full, ...") that
    are the run's, so they are not drawn under a module. The "Modules delivered" card, run code and hash, and the
    download stay the run's.
  - The Trace and Gaps pages are keyed by `item/restarts` so that a new item address, or picking the address already
    shown, still starts the page afresh.
- `web/src/pages/library/parts/ModuleFilter.tsx`: `useModuleFilter(options, address = null)`. `address` names the
  item an address opens; reaching a new one sets the filter back to All (state adjusted during render, no effect),
  so an item address still draws its row, as `EvidenceAddress.test.tsx` requires. `clear` and the focus on the Module
  button (T30) are unchanged.
- `web/src/pages/library/EvidenceRecord.tsx` (S4-008, S4-009, and the filter on Record):
  - `withoutCodes` leaves the delivered `Code` column (found by its head, searched from column 1) out of the heads, every
    row and the Total row; every other head and cell is as delivered. Each module's name stays. The two CSS rules that
    set the second column left and monospace for the code are gone, and the bold Total rule stays.
  - `Calls`: when the table lists fewer modules than the run holds (`run.modules.length`), a sentence under the table
    reads "4 of 13 modules shown. The Total row is the delivered total for the run." Counts only: the data holds no reason
    the list is partial, so none is given. The rows are not summed.
  - With a module chosen, Module timings and Model calls draw that module's row only; Model calls draws no Total row and no
    count badge (they are the run's; Trace and Gaps already drop the delivered count under a module). A module with no row
    in a table gets the library's empty state ("No time is listed for X", "No model calls are listed for X") with "Show all
    modules" as its way back (focus goes to the Module button). The hashes, the spend and the registers are the run's and
    are not narrowed (a register's "written by" is free text, not a module id).
- Module timings: its delivered note already reads "... Six of thirteen shown." The slice holds only those six rows, so a
  "Show all modules" control would have nothing to show; none was added. With the held filter, choosing any other module
  on Record now says that no time is listed for it.
