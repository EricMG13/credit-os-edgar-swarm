  PCs with a mouse. A finding that shows only at 480 px or less, on touch or with the keyboard alone is no
  longer a defect. C1-003's phone-width half (Ended, State and Reason unseen on a phone at 390 px) is therefore
  not repaired and no time was spent on it. No focus or keyboard work was added.
- **R16 (owner, 2026-11-17, relayed by the lead): "screen reader - not required".** A finding that changes only
  what a screen reader announces is no longer a defect. **C1-006 (a live region on Run activity) is dropped.**
  I had written it (a polite status region, with the sentences computed from the previous and next list, and
  tests); the code and its tests were taken out again before the commit. The C1-006 probe reproduces again on the
  final build, as it should (exit 1 below). The visible alert of C1-031 and of the Library read failure are
  unchanged by R16: the `Alert` component carries its own role, and nothing was built for announcements.
- R5: nothing the reader sees was removed (see "What the reader sees, before and after").

## Causes

- **C1-002.** `ReportLibrary` drew a bare `<p className={card}>No reports yet</p>` for a null index, and for an
  index with no report `MatchRuns` drew the Sector and Pathway selects and the Cards/List toggle over the same
  bare card. Two forms, no icon, no sentence, no next action in the body.
- **C1-003 (desktop half).** The Waiting table sits in the right column of a two-column grid fixed at `440px`
  (`xl:grid-cols-[minmax(0,1fr)_440px]`). With realistic names the table is 464 px wide, so the Pathway column
  ("Deep credit assessment") was cut at the panel edge at 1280 and 1440 px.
  The finding names the panel's `overflow-hidden` as the cause. Measured, that is only part of it: the `Table`
  component (not mine, unchanged) already wraps its table in its own `overflow-x-auto` div, and that div does
  scroll (`scrollWidth` 464 against `clientWidth` 438, scrolls 26 px). So the content was reachable by scrolling
  but drawn cut off mid-word with no cue, because the column was 24 px too narrow. The repair is the column's
  width; the panel class is changed as the finding suggests (see the probe note).
- **C1-031.** `useActivity` turned any failed or malformed poll into the string `"unreadable"`, which replaced the
  whole page content (counts and every run card) with the neutral `EmptyState` (magnifier icon, no tone), even when
  the previous read was good.
- **C1-004, Library read failure.** The Library's `useResource` error was drawn by `ErrorNotice`: one bordered
  line of red text with no icon and no action, and no way to ask again (`useResource` never clears an error).

## C1-004: does it cover the Library's read failure?

Yes. The register's C1-004 evidence lists `web/src/pages/connected/LibraryIndex.tsx:216` ("The Library's own read
failure (LibraryIndex.tsx:216) is the same plain line") and its expected behaviour is "errors are the alert
component with tone by severity and an action". The probe `c1-004-error-states.cjs` prints this state as
`library read fails`. T04 repaired the run pages; I repaired the Library the same way (an `Alert` with an action,
existing components unchanged). The report half of C1-004 (unknown or unpublished report) is T17 and was not
touched.

## What changed (all in `web/src/pages/connected/`)

- `LibraryIndex.tsx`
  - New `EmptyLibrary`: the `EmptyState` component as it is (featured icon `BookOpen01`, title "No reports yet",
    one sentence "A report appears here once a run has finished.", and a secondary "Start a run" button to
    `/start`; the header's own primary "Start a run" stays). A null index and an index with no report are now
    this one form, and the Search issuers box, Sector and Pathway selects and the Cards/List toggle are not drawn
    while there is nothing to filter (C1-002). The Search box was already hidden for an empty index.
  - `MatchRuns`: the branch that said "No reports yet" under live filters could not be reached once there is a
    report (an empty filter always matches), so it is gone; the branch for filters that match nothing still says
    "No issuers match these filters." and keeps the filters.
  - New `useLibrary` (replaces `useResource(getLibraryIndex)` in this file; `useResource` is unchanged and still
    used elsewhere): the same one request, plus `retry`, and a failure stays on screen until the next answer, so
    the pressed button keeps its place and a success clears the alert.
  - A read failure is an `Alert` (error tone, icon) with a "Try again" button: "The service cannot be reached"
    (a request that never arrived; the browser's own "Failed to fetch" is not drawn) or "The library could not be
    loaded" with one sentence each (C1-004, Library).
- `RunActivity.tsx`
  - `useActivity` returns `{ read, failed }`: `read` is the last list that read well and stays on screen; `failed`
    says the latest poll did not (a failed request or an answer with no `runs` list).
  - A failed read is an `Alert` with a "Open the library" action (the button the old empty state had): with no
    list yet, an error "Run activity could not be read" with the old sentence unchanged ("Nothing is claimed about
    runs in progress, waiting or ended without a report. This page reads it again every few seconds. Finished
    runs are in the library."); with a list, a warning "Run activity could not be refreshed" with "Showing the
    list as it was at <time>. This page reads it again every few seconds." The counts, run cards, tables and the
    "Updated" stamp keep the last good read. The next good read removes the alert (C1-031).
  - The Waiting and Ended panels are `overflow-x-auto`, not `overflow-hidden`, and the Running/Waiting grid is two
    equal columns at xl (`xl:grid-cols-2`), not `1fr 440px`, so the Waiting table is 560 px (1280) or 640 px (1440)
    wide and holds "Deep credit assessment" whole (C1-003, desktop).
- Not changed: `layout.tsx` (`ErrorNotice` is still used by `StartRun` and `ReportReader`), `useResource.ts`,
  `empty-state.tsx` (used as it is, per the task note), `Alert`, `Table`, `api.ts`, `RunProgress.tsx` (T04's
  states are untouched; I did not need to change it), and nothing under `web/src/pages/signal/`.

## What the reader sees, before and after (fidelity check, draft for `VERIFICATION.md`)

Scope: the connected Library (`/`) and Run activity (`/runs`) pages in the synthetic proof service at 1440 and 1280 px,
with the responses the C1 probes supply in the browser (an empty library, a Library answered with 500 or a refused
connection, an activity list with one running run, four waiting and four ended runs, and a poll sequence of good,
500, good). The handoffs behind these pages are synthetic. Nothing under a report was touched.

- Unchanged: every figure, name, period, state word, reason, time stamp and count on Run activity (Running 1,
  Waiting 4, Ended 4, "Updated 17 Nov 2026, 08:00 UTC", the modules and the "2 source files" line); the old
  sentence of the unreadable state; the "Open the library" action; the Library's "No reports yet" words; the
  Library's filters and layout toggle when there is a report; "No issuers match these filters." with its filters.
- Changed on purpose: the empty Library is an icon, the title, one sentence and a "Start a run" button, with no
  filters or layout toggle over nothing; the Library read failure is an alert with an icon and "Try again" and
  names an unreachable service in words; a failed poll of Run activity keeps the last good list with a warning
  and its time, or on a first read is an error alert, instead of the neutral empty state; the Waiting table is
  not cut off at 1280 and 1440 px because its column is wider (two equal columns, was 1fr and 440 px).
- Removed: nothing the reader saw. The unreachable "No reports yet" branch under filters has no effect.

## Not verified

- Phone and narrow widths: the Waiting and Ended tables at 768 px and 390 px are as before (Ended rows 244 px tall
  at 768 and 390, content reached by scrolling), by R14; no keyboard, focus or touch work was done.
